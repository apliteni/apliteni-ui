# Drawers

## One-record drawer

<!-- rule: one-record -->

**Rule:** Open a drawer to view or change one record without leaving its list.

**Why:** Closing the drawer returns the user to the opened row.

**Do:** Use a drawer for a short filter, a new key, or a reclassification.

**Don't:** Use it for work needing an address, multiple screens, or steps; use a page instead.

**Except:** Two-answer questions use confirm. Short forms fit; forms needing steps or more than one screen use a page.

## Grouped content

<!-- rule: no-cards -->

**Rule:** Group drawer content under headings and never put a card inside it.

**Why:** The drawer already provides the edge and raised surface, so cards add unnecessary boxes.

**Do:** Use three groups, with a heading over each group’s rows and one line between groups.

**Don't:** Put each group in a card inside the drawer.

## Three divider lines

<!-- rule: three-lines -->

**Rule:** Draw lines under the header, over the footer, and between each group; draw no other lines.

**Why:** These lines mark scrolling boundaries and separate groups, not rows.

**Do:** Separate header, footer and groups.

**Don't:** Add dividers between every row.

## Spaced label rows

<!-- rule: rows -->

**Rule:** Put each value beside its label and separate rows with space.

**Why:** In a drawer up to 560px wide, labels and values stay together at any zoom without row lines.

**Do:** Place a short value beside its label, such as `Status — Active`.

**Don't:** Put the value at the far edge and use row lines to guide the eye back.

**Except:** Put figures readers compare down the panel, such as amounts, in a table using `table()` and right-align them.
