# The page

## Keep one shell

<!-- rule: layout -->

**Rule:** Use one shell throughout the product: the rail alone, or the rail with a bar above the page for search and the reader’s menu.

**Why:** Readers learn where search and account controls are once.

**Do:** Use the same shell on every screen.

## Choose content width

<!-- rule: width -->

**Rule:** Use the wide column for mostly tables and boards, and the centred column for mostly reading and forms.

**Why:** Tables need space, while reading needs a line length readers can follow.

**Do:** Show every table column at once in the wide column.

**Don't:** Put the same table in the centred column when its last column goes off-screen.

## Order page headings

<!-- rule: head -->

**Rule:** Put the way back first, then the page title and a short introduction, with everything else below.

**Why:** Readers should know which page they are on before choosing filters.

**Do:** Back link, then title, then introduction, then filters.

**Don't:** Put filters above the title.

**Except:** Small tools for the whole page, such as a version badge, stand at the end of the title row.

## Use one page title

<!-- rule: one-h1 -->

**Rule:** Give each page exactly one page title.

**Why:** Readers using heading navigation need one clear place to land.

**Do:** Use one h1 for the page.

**Don't:** Use multiple page titles or none.

## Follow heading levels

<!-- rule: outline -->

**Rule:** Use headings in order without skipping levels, and stop at h3: page, section, then group. Make a card title a heading one level below its parent, styled by its class.

**Why:** Skipped levels hide structure, and a fourth level usually means the page should be split. A card title in a div is not in the outline.

**Except:** A card in a section with its own h2 uses h3.

**Do:** Use a page heading, then section headings, then group headings.

**Don't:** Skip from the page heading to a group heading, or add a fourth heading level.

## Emphasize one action

<!-- rule: one-primary -->

**Rule:** Use one filled button for the main action and give all other actions less emphasis. In a pair, fill the committing action, such as Save beside a ghost Cancel. Keep labels and values in neutral ink.

**Why:** Equal emphasis makes the main action unclear, and one accented action is easier to find than many.

**Except:** Badge success, pending and danger keep their status colours, never the accent.

**Do:** Make Create token primary, with Import agents and Export less prominent.

**Don't:** Give all three actions equal emphasis.

## Limit card stacks

<!-- rule: stacking -->

**Rule:** Stack no more than six cards.

**Why:** Too many cards make readers scroll past other content to find their target.

**Do:** Show up to six cards.

**Don't:** Show twelve cards.

## One frame per block

<!-- rule: one-frame -->

**Rule:** Never put a block inside another block with the same border.

**Why:** Two equal borders draw two edges for one group, so the reader cannot see which block holds which.

**Do:** Put the filter bar and the table card directly on the page.

**Don't:** Put the filter bar and the table card inside one more card.

## Leave pages closed

<!-- rule: at-rest -->

**Rule:** Show the page uncovered until the reader chooses to open something.

**Why:** An overlay on arrival interrupts reading and can move keyboard focus.

**Do:** Let the reader open a menu or dialog.

**Don't:** Open either automatically when the page loads.

## Keep table density consistent

<!-- rule: density -->

**Rule:** Use compact rows in every table on the page, or use compact rows in none of them.

**Why:** Consistent row heights make tables feel like one page.

**Do:** Use compact rows in both tables.

**Except:** Use the spacing required by the busiest table.

## Write a useful introduction

<!-- rule: lede -->

**Rule:** A page may open on its title alone. If it has an introduction, keep it to two sentences or fewer. Give only a purpose or step that the title and controls do not show.

**Why:** Repeating the title wastes the reader’s time and loses their place.

**Do:** Below “Payouts”, say “Payouts arrive within three business days.”

**Don't:** Write “This is the payouts page” below “Payouts,” or keep a line there because the page looks bare without one.
