# The page

What belongs on one page: where readers begin, the first action, and when to split content.

## Choose one shell layout for a product and use it on every screen: either the rail alone or the rail with a bar above the page containing search and the reader’s menu.

<!-- rule: layout -->

**Why:** Readers learn where search and their account are once; moving either makes them relearn it on every page.

## Use the wide content column for mostly tables and boards, and the centred column for mostly reading and forms.

<!-- rule: width -->

**Why:** A table in the centred column may lose its last column off the side; a full-page paragraph may become too wide to follow back across.

**Do:** Drawn to scale: the wide column shows every table column at once.

**Don't:** The same table in the centred column at the same scale: the last column is off the side.

## Put the way back first, then the page title and a short introduction; put everything else below.

<!-- rule: head -->

**Why:** Filters above the title make readers choose before knowing which page they are on.

## Give each page exactly one page title.

<!-- rule: one-h1 -->

**Why:** Without a page title, people navigating by headings have nowhere clear to land, as the access confirmation screen once showed.

## Use headings in order without skipping levels, and stop at h3: page, section, then group.

<!-- rule: outline -->

**Why:** Skipping a level makes content seem missing; needing a fourth means the page should be split.

**Do:** These labels show heading levels, not headings on this page; each level belongs to the one above it.

**Don't:** Broken heading order makes readers guess which content belongs together.

## Use one filled button for the main action and give other actions less emphasis.

<!-- rule: one-primary -->

**Why:** When several buttons stand out equally, readers must determine which action matters most.

**Do:** Readers can start with Create token without comparing it first with Import agents and Export.

**Don't:** All three actions have equal emphasis, so the main action is unclear.

## Stack no more than six cards, and do not put cards inside other cards.

<!-- rule: stacking -->

**Why:** With twelve cards, readers may scroll past eleven to find the one they need.

**Do:** Each block represents a card: six cards reach the limit.

**Don't:** Twelve cards exceed the limit; the blocks use the same scale in both examples.

## Show the page uncovered until the reader chooses to open something.

<!-- rule: at-rest -->

**Why:** Opening something over the page on arrival interrupts reading and can move keyboard focus.

## Use compact rows in every table on the page, or none of them.

<!-- rule: density -->

**Why:** Consistent row heights make tables feel like one page; use the spacing required by the busiest table.

**Do:** Both tables use compact rows, so spacing stays consistent.

**Don't:** The tables have the same four columns, but the rows above are compact and those below are roomy.

## Keep the introduction to two sentences or fewer, and add information the title does not give.

<!-- rule: lede -->

**Why:** “This is the payouts page” below “Payouts” uses the reader’s time without adding anything new.
