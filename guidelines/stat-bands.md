# Stat bands

## Use a stat band

<!-- rule: a-band-not-a-card -->

**Rule:** Put key figures in a stat band, not a card of parts.

**Why:** A shared layout puts each figure's value, change and basis in one place.

**Do:** One card per figure: the figure largest, an arrow, a signed change, one caption above the row.

**Don't:** Heading-size figures, a capitalised 10px status chip, no basis.

## Colour by meaning

<!-- rule: tone-not-direction -->

**Rule:** Colour a change by whether it is good news, not by whether it rises or falls.

**Why:** Direction alone does not show if a change is good.

**Except:** An omitted or “neutral” tone keeps the arrow and comparison without colour, for unscored volume, reader-dependent meaning and net cashflow that income less cost already explains.

**Do:** Four verdicts. Rising Income and Cost have opposite colours. Falling Unclassified is green. Undeclared Net cashflow stays grey.

**Don't:** Four figures coloured by sign: three rises green, cost growth praised, the year’s cleanup red.

## State the comparison basis

<!-- rule: say-the-basis -->

**Rule:** State in reachable text what each change is measured against.

**Why:** A percentage needs a basis readers can find.

**Except:** If the visible control names the period, the basis can be for screen readers only. Use this exception for the Finance dashboard pattern.

**Do:** The basis once, before and outside every figure, in a caption each change refers to or beside one exception.

**Don't:** A title attribute, the note below the tiles or inside the first figure, no basis, nested captions.
