# Selection bar

Best for: A table where one change applies to several selected rows.
Row opens: Nothing. The checkbox changes the selection.
Status: Proposed pattern. The owner has not approved or installed it.

## Structure

Keep the table in place. Put the bar after the table in page flow.
Reserve space for the bar below the last row.
Keep the bar near the bottom while the table scrolls.

Show the count, equal-width fields, Apply and Clear.
Show each field name until the person picks a value.
After a pick, show only the value.
Keep the full value in the accessible name and hover title.

## Behavior

With no selected rows, hide the bar.
Keep Apply off until a field has a value.
Apply sends all set fields in one call.
Keep fields and Clear off while Apply is busy.

A opens field lists above the bar in the page theme.
At narrow widths, put the fields above the count and actions.
B instead puts the fields in an overflow panel. B changes the issue requirement.

## Keyboard

Keep the count outside the Tab order.
Use Tab for fields, Apply and Clear.
Use arrow keys inside a field list.
Escape closes the list and returns focus to its trigger.
With no open panel, Escape clears the selection.
Clear returns focus to the table selection control.
Announce the count through a polite status region.

## Design handoff

Use the approved kit tokens, not values from a sketch.
